# 环境准备与实验复现

当前仓库包含 AFDM 软件基准入口，以及厂家 OFDM 板端流程与实验记录。以下硬件步骤用于复现；具体板卡操作、供电、启动方式和射频限制以对应厂家指南为准。

## 运行 AFDM 软件基准

1. 保留 OFDM Notebook 和已保存的数据。停止动态图表刷新并保存原 Notebook。
2. 在 JupyterLab 根目录点击上传按钮，选择本仓库的 `notebooks/02_afdm_software_baseline.ipynb`。
3. 打开上传的 Notebook，使用新的 Python 3 内核，按顺序运行全部代码单元格。此 Notebook 仅依赖 NumPy，不导入 PYNQ，不控制 FPGA。
4. 预期出现 PASS 1～6，以及按 Es/N0 统计的 AFDM/OFDM AWGN BER 表。无噪声收发比较 65536 个已知比特，预期 0 错误；这是软件模型结果。
5. 最后一格将 `summary.json` 和 `reference_vectors.npz` 保存到当前目录下唯一命名的 `afdm_results_...` 文件夹。下载这些文件与执行后的 Notebook，记录软件版本和运行位置。

电脑端已执行全部代码并通过。板卡 Python 环境复现仍待用户操作；即使在板卡 CPU 中运行通过，也不表示 AFDM 已进入 PL 或完成射频收发。此初版不含 CPP、多径、多普勒等；随后逐步加入。

## 运行 CPP 与静态多径软件实验

1. 保存并下载 02 的输出。用户已反馈其运行至 `afdm_results_7559efb0`，具体结果 JSON 仍待核对。
2. 上传 `notebooks/03_afdm_cpp_multipath.ipynb`，用新的 Python 3 内核运行全部单元格。文件包含所需函数，只依赖 NumPy，无需先运行 02，不控制 FPGA。
3. 预期 PASS 1～8；三种模式在无噪声 ZF 检测后各比较 32768 比特，错误数均为 0。带噪声时查看 LMMSE 表，保留实际误码数。
4. 下载 `afdm_cpp_results_.../summary.json`、`reference_vectors.npz` 以及执行后的 Notebook。

信道是已知的三条固定路径，默认整数时延 0/2/5，CPP 长度 16，假设完美定时与零频偏。一般 CPP 使用独立参数测试，另检查满足条件时退化为 CP。接收使用真实有效信道矩阵的 ZF/LMMSE；信道估计、同步、多普勒和射频均未实现。此实验不用于宣称 AFDM 的多普勒性能优于 OFDM。

## 运行整数与分数多普勒软件实验

上传 `notebooks/04_afdm_doppler_known_channel.ipynb`，在新的 Python 3 内核中运行全部代码。文件独立且仅依赖 NumPy，不加载硬件；预期最终输出 `PASS 8/8`、无噪声六组各 `0 / 32768`，并保存 `afdm_doppler_results_.../summary.json` 与参考向量。

使用静态 `[0,0,0]`、整数 `[0,1,-2]`、分数 `[0.25,1.4,-1.7]` 三组归一化多普勒（单位为子载波间隔），符号约定 `exp(-j*2*pi*nu*n/N)`。CPP 长度 16，路径时延 0/2/5。连续块不复位路径相位，单独检查第二块的绝对时间；误码表按相同起点的独立块统计。AFDM 和 OFDM 均使用完整已知信道检测，未引入导频估计或同步。

将执行后的 Notebook、最终汇总、保存位置与结果 JSON 留存。单个固定信道的统计不用于宣称普遍的 AFDM 性能优势。随后进入导频与信道估计；射频与 FPGA 仍需独立开发。

## AFDM 后续验收顺序

| 顺序 | 工作 | 验收依据 |
|---|---|---|
| 1 | 导频和信道估计 | 从导频得到信道，记录估计误差及估计信道检测的 BER，并和真实信道检测对照 |
| 2 | 成帧、定时/频偏同步、消息校验 | 未知帧位置与频偏下恢复有效载荷，用帧号、CRC、BER/PER 判断正确性 |
| 3 | 板上任意 I/Q 回放与接收采集 | 可从源码重建适配工程，打通 BRAM 或 MM2S 回放及接收采集，明确格式与速率 |
| 4 | AFDM 射频离线原型 | 软件生成的已知波形经 DAC、TX4→RX2、ADC 后，保存采样并离线恢复数据 |
| 5 | 定点化与 PL 实时实现 | 浮点/定点/RTL 逐级对照，先发射再接收，选择资源和吞吐可接受的检测器 |
| 6 | 持续运行与性能验收 | 记录时序、丢数/溢出、BER/EVM、吞吐与重复启动；受控信道中公平比较 OFDM/AFDM |

第 3 项的板卡工程、版本和接口核对可与第 1、2 项并行。现有厂家 OFDM 通路需要新增任意 I/Q 回放能力；完成软件 Notebook 不会自动把现有 OFDM bitstream 变成 AFDM。

## 判定与归档

### 星座观察完成后的数据留存

以下适用于本机已检查的厂商 `rfsoc_ofdm` 驱动；尚未在本次会话中执行板上采集。

1. 保存成功运行的 Notebook 副本及 QPSK、16-QAM 截图，记录实际接线、调制、增益和版本。
2. 在原 Notebook、原内核中保持 `ofdm_hw` 对象有效。选择目标调制后，按各图表的方形停止按钮停止自动刷新，等当前刷新结束。停止的是图表采集，不关闭收发链路。
3. 调用 `ofdm_hw.inspectors['constellation'].get_frame()` 获取一帧复数数组，用 `numpy.save` 保存；分别保存 QPSK 和 16-QAM，避免覆盖。
4. 同时保存实际调制、增益、采集时间、样本数、dtype、观察点及软件/bitstream 信息。此接口的数据来自接收星座观察点，驱动按 `2^-14` 缩放；未经核对不要将其采样率填为 ADC 采样率或默认的 20 MS/s。
5. 用 `numpy.load` 重新加载文件，以实部/虚部作散点图。下载 `.npy`、元数据与 Notebook 到电脑，作为后续离线分析基线。
6. 完成三次独立启动或按原 Notebook 重新初始化的复现。归档后再推进已知数据、帧对齐与 BER/CRC 校验。

### 三轮独立初始化验证

每轮先停止所有图表自动刷新，保存 Notebook，使用 Kernel 菜单重启当前 Notebook 的内核。只选择重启内核，不使用自动运行全部单元格。保持原 TX4 → RX2 接线和增益配置，按原顺序重新执行导入、`ofdm_hw = Overlay()`、调制选择控件和接收星座控件。每轮重新产生数据，不能用 Notebook 重启前留下的图片作为当轮结果。

依次选择 QPSK、16-QAM，各启动刷新观察约一分钟，记录点簇、更新情况和异常；停止刷新并等当前采集结束后，再运行采集与重绘单元格。每轮各保存两种调制的一份数据，记录轮次、路径、样本数与保存前后一致性。三轮均需重新启动内核并加载 Overlay，不能把同一初始化中的三次采集计作三轮独立初始化。若单元格持续处于 `[*]` 或报错，保留现象与输出，暂停后续轮次。

验收记录分别填写三轮的初始化状态、QPSK、16-QAM、数据保存和异常。整板重新上电测试另行记录，不根据内核重启测试推断其结果。

### 从 02 切换到 03 综合界面

本机厂商包的 `03_voila_rfsoc_ofdm_demonstrator.ipynb` 仍加载相同的 OFDM Overlay，再调用 `ofdm_hw.ofdm_loopback_application()`，提供收发时域、频谱和接收星座的综合界面。它可以在 Notebook 中依次执行三个原有代码单元格来检查界面；Voila 的独立仪表页面可后续再测。

切换前先停止 02 的图表刷新并保存，通过 Kernel 菜单关闭 02 的内核；仅关闭标签页可能仍保留后台内核。保持 TX4 → RX2 回环，再打开 03，依次执行导入 `Overlay`、`ofdm_hw = Overlay()`、`ofdm_hw.ofdm_loopback_application()`。避免两个内核同时控制同一 FPGA 及 DMA。核对 QPSK/16-QAM 星座，以及收发时域/频谱页的刷新情况。03 结果与三轮独立初始化、BER、AFDM 分别记录。

能显示星座不等于已经验证自定义消息、BER 或 AFDM。分别标注“启动通过”“OFDM 观察通过”“数据校验通过”等实际达到的结论。

原始采样可保存在本地 `captures/`，生成产物可放在 `artifacts/`；两者默认忽略。在 Git 中提交参数、脱敏日志摘要、可公开的小图表和样本的校验值/存储说明。未经公开许可的厂家材料和研究资料留在本地。

遇到问题时，记录执行入口、完整错误的脱敏版本、预期与实际结果、最近改动，以及可重复执行的步骤。硬件验证尚未执行时，不填写“通过”。
